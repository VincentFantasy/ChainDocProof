# 4. 用户端

日期：2026-10-15
状态：需求已确认

## 背景

MVP（需求 1）与管理端（需求 2/3）已完成，用户端前端当时明确暂不实现。
后端用户端 API（钱包签名登录、次数查询/购买、文件上传、存证、校验、列表）已全部就绪，
本需求补齐用户端前端，产品对用户可用。

## 需求

### 登录
1. 连接 EIP-1193 钱包（MetaMask 等）后才能使用；未安装钱包给出安装提示。
2. 校验钱包网络为 Sepolia 测试网（chainId 11155111），不一致时提示钱包切换，切换失败引导手动切换。
3. 钱包对明文 `"ChainDocProof:" + 地址` 做 EIP-191 个人签名（personal_sign）提交后端登录，获取 token。
4. token 失效（后端重启 / 过期，401）时回到登录页，重新连接钱包签名即可，无需注册。

### 次数与购买
5. 顶部常驻显示剩余次数与当前钱包地址（缩写）。
6. 购买页展示：剩余次数、购买单价（10 DocToken/次）、钱包 DocToken 实时余额（链上 eth_call）、后端收款地址（可复制、可查 Etherscan）。
7. 购买次数：输入数量（1~1000），前端计算链上转账金额 = 数量 × 单价（BigInt 运算防精度丢失）；
   经钱包发送 DocToken ERC20 转账交易到后端收款地址，等待链上确认后自动携带交易 hash 调后端购买接口完成购买；
   后端链上核验转账、txHash 幂等（重复提交提示"该交易已用于购买"）。
8. 钱包 DocToken 余额不足时提前拦截并给出缺额提示；说明 DocToken 获取途径（ETH 链上兑换 / 管理端发放）。

### ETH 兑换 DocToken（2026-10-15 补充）
9. 购买页提供"ETH 兑换 DocToken"卡片：展示链上汇率（eth_call 读 DocToken 合约 `ethPerToken()`，1 DocToken = X ETH）
   与钱包 ETH 余额（`eth_getBalance`），两者均可手动刷新。
10. 兑换：输入兑换 DocToken 数量（≥1 整数，前端设上限），前端计算应付 ETH = 数量 × 汇率（BigInt 运算，与合约算法一致）；
    经钱包向 DocToken 合约发送 `buyTokens(数量wei)` 交易（msg.value 带应付 ETH，合约多付自动找零），
    等待链上确认后刷新 DocToken 余额；ETH 余额不足提前拦截；用户拒绝 / 交易失败 / 超时给本地化提示。
11. 兑换成功后用户即可用钱包中的 DocToken 走"购买次数"流程（转 DocToken 给后端收款地址）。

### 存证
12. 选择文件（≤50MB，前端校验）上传，后端只计算 SHA-256、文件不落盘；
    60 秒内只能上传 1 个文件（后端限流，前端解析错误提示中的秒数，按钮禁用并倒计时；刚上传成功也主动倒计时 60 秒）。
13. 上传成功后记录为"待上链"（PENDING），点击"存证"扣 1 次，后端把 hash + 上传时间戳写入存证合约；
    上链成功后记录变为"已上链"（STORED），展示链上交易 hash 并可跳转 Sepolia Etherscan。
14. 剩余次数为 0 时点击存证/校验提示"次数不足，请先购买"并引导跳转购买页。

### 验真
15. 对"已上链"记录点击"校验"，重新上传原件，后端与链上 hash 比对并扣 1 次，弹窗展示"文件未被篡改 / 文件已被篡改（哈希不一致）"。

### 列表
16. 存证列表展示：文件名、大小、文件哈希、上传时间、状态、链上交易、操作列（存证 / 校验）。

### 界面
17. 中英文可切换（vue-i18n），风格与管理端一致；登录页独立全屏，主页面侧边栏布局（存证 / 购买次数两个菜单）。

## 约束

- 不新增后端 API；链 id、DocToken / DocProof 合约地址等公开信息作为前端常量。
- 技术栈与管理端一致：Vue 3 + Vite + JS + Element Plus + vue-i18n，hash 路由，不引入状态管理库。
- 钱包交互使用浏览器原生 `window.ethereum`，不引入 ethers；ERC20 的 transfer / balanceOf 与 DocToken 的
  buyTokens / ethPerToken 用最小 ABI 编码实现（纯函数，带单测）。
- ETH 兑换汇率是链上公开值（DocToken 合约 getter），前端 eth_call 直读，不为此新增后端接口。
