# 5. 购买时销毁 DocToken

日期：2026-10-15
状态：需求已确认

## 背景

MVP（需求 1）、管理端（需求 2/3）与用户端（需求 4）已完成。原设计中 DocToken 的销毁发生在**存证**环节：

- 用户购买"次数"时把 DocToken **转给后端地址**（带 txHash 确认），后端发放 `t_user.credit_balance`；
- 之后每次存证 / 校验由后端用管理钱包把 1 枚 DocToken 烧进 0 地址（`DocProof.storeProof → token.transferFrom(admin, 0x0, costPerProof)`），DocProof 因此持有 `token / costPerProof / owner / onlyOwner` 与"存证费用"管理接口。

问题：① 代币的销毁与消耗被拆到两个环节、两个主体（用户转账、管理钱包销毁），链路绕；② DocProof 被耦合进代币经济（持有代币、需 approve、需管理端调费用），职责不清；③ 用户转给后端地址后若后端未上链，资金停留在后端而非销毁，语义偏弱。

本需求改为**购买时销毁**：购买即全额销毁（预付费），存证不再销毁代币。

## 需求

### 核心链路（已确认的方案 A）

1. **买 DocToken（不变）**：钱包 `buyTokens(ETH→DocToken)`。
2. **买次数（改）**：用户**销毁自己的 DocToken**（新增 `DocToken.burn(uint256)`，打进 0 地址），金额 = 单价 × 数量；
   后端链上核验 `Transfer(用户 → 0x0, 金额)` 后发放 `t_user.credit_balance`（txHash 幂等）。
3. **存证 / 校验（改）**：后端扣 `credit_balance`；`DocProof.storeProof` 只写链上记录（hash + 时间戳 + 存证方），
   **不再销毁代币**；DocProof 去掉 `token / costPerProof / owner / onlyOwner / setCostPerProof / CostUpdated`，构造函数改为**无参**。

经济语义变化：购买即全额销毁（预付费），不再按次从管理钱包销毁。

### 合约

4. `DocToken` 新增 `burn(uint256 amount)`：`require(balanceOf[msg.sender] >= amount)`、`balanceOf[msg.sender] -= amount`、
   `totalSupply -= amount`、`emit Transfer(msg.sender, address(0), amount)`；删除无人调用的 `burnFrom(address,uint256)`；
   保留标准 `transfer/approve/transferFrom/allowance`（ERC20 惯例）。
5. `DocProof`：删除 `IToken` 接口、`token`、`owner`、`costPerProof`、`setCostPerProof`、`CostUpdated` 事件、`onlyOwner` modifier；
   `storeProof` 去掉 `token.transferFrom(...)`，只写 `proofs / hashIndex / ProofStored`（`Proof.owner` 字段保留，记录存证方）；
   `constructor()` 改为无参。
6. 两合约重新编译（`npx -y solc@0.8.24 --bin`），替换 `.bin`。

### 后端

7. `PurchaseService`：`hasTransfer` 的 to 由管理地址改为 0 地址常量（`ZERO_ADDRESS = "0x" + "0".repeat(40)`）；
   失败文案"转给后端地址"→"从当前钱包销毁"；`expectedValue`（单价 × 数量）不变。
8. `AdminService` / `AdminController`：删除存证费用查询 / 调整接口（`GET/POST /admin/proofs/cost`）、`ProofCostReq` 与 `MAX_COST_PER_PROOF`；
   `ChainGateway` 删除 `getCostPerProof()` / `setCostPerProof()`（`hasTransfer` 通用实现保留）。
9. `CreditVo` 去掉 `backendAddress` 字段；`UserCreditController` 相应精简；`ProofService` / `application.properties` 注释措辞更新。

### 用户端

10. `wallet/abi.js` 新增 `BURN_SELECTOR = '0x42966c68'` + `encodeBurn(amountWei)`，删除 `TRANSFER_SELECTOR` / `encodeTransfer`；
    `wallet/wallet.js` 新增 `burnDocToken(amountWei)`（`eth_sendTransaction` 到 DocToken，`data=encodeBurn`、`value='0x0'`），删除 `transferDocToken`。
11. 购买页 `BuyView` 改调 `burnDocToken`，删除"后端收款地址"UI 块与复制按钮；文案"转账"→"销毁"（中英对齐）。

### 管理端

12. 删除"存证费用"页面（`ProofCostView.vue`）、`admin.js` 的 `getProofCost/setProofCost`、路由与菜单、i18n 文案块。

## 约束

- 不新增后端 API，只删除存证费用相关接口；存证 / 校验仍各扣 1 次 `credit_balance`，业务规则不变。
- 技术栈不变：Solidity 0.8.24、Spring Boot 3.4 + Spring JDBC + web3j 4.12.3、Vue 3 + Vite + Element Plus + vue-i18n、
  用户端原生 `window.ethereum` + 手写最小 ABI 编码（不引入 ethers）。
- 保持代码简洁、重要方法加中文注释、补充 / 更新单测（购买链上销毁金额校验、burn ABI 向量、边界与异常分支）。

## 部署影响

`DocToken`（新增 burn）与 `DocProof`（构造函数变更）**必须重新部署** → 两个新合约地址 →
同步更新后端 `contract.doc-token` / `contract.doc-proof` 与用户端 `client/src/config.js` 两常量；
新 DocToken 需重新 mint 库存并重置汇率；管理钱包不再持有用于销毁的 DocToken。
