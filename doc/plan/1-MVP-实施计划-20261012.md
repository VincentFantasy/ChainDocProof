## 二、整体架构与经济闭环

```
用户 ETH ──(链上 buyTokens)──> DocToken ──(用户钱包转给后端地址)──> 调购买接口(链上验证)──> 次数
次数 ──> 存证(后端调 storeProof，消耗后端钱包 DocToken 并销毁) / 校验
```

- 后端不上链存文件：上传仅流式计算 SHA-256，文件不落盘、不缓存
- 存证上链内容：hash + 时间戳（+ 证明人、区块时间、序号）

## 三、合约 `contract/`

### DocToken.sol（ERC20，owner = 管理端部署私钥地址）
- 标准 transfer / approve / transferFrom / burnFrom（allowance 模式）
- `mint(address to, uint256 amount)`：onlyOwner，管理端发放
- `buyTokens()` payable：固定汇率兑换（`ethPerToken` 可变变量，owner 可调；合约需先由 owner mint 库存到合约地址）
- 统计：`buyCount` 计数器 + `BuyTokens(buyer, ethAmount, tokenAmount)` 事件
- 每个函数加中文注释

### DocProof.sol（存证合约）
- 构造函数注入 token 地址与 `costPerProof`（每次存证消耗 DocToken 数量，owner 可调）
- `storeProof(bytes32 hash, uint256 timestamp)`：
  1. `token.transferFrom(msg.sender, address(0), cost)`（消耗后销毁）
  2. 写入 `Proof(index, hash, timestamp, owner, blockTimestamp)`，emit `ProofStored`
- 查询：`proofCount()`、`proofs(i)`、`getProofIndexByHash(hash)`
- 每个函数加中文注释

> 合约由用户自行部署到 Sepolia（Remix 等工具均可），部署后把地址填入后端配置。

## 四、后端 `server/`（Spring Boot 3.x + JDK 21 + Spring JDBC + web3j，Maven）

包结构按 AGENTS.md：`config / dao / interceptor / model / service / support / web`
依赖尽量精简：spring-boot-starter-web、starter-jdbc、mysql-connector-j、web3j core、spring-security-crypto（BCrypt）、h2（仅测试）。

### 关键服务（重要方法加中文注释）
- **AuthService**：钱包签名登录（EIP-191 + ecrecover），发内存 token（ConcurrentHashMap + TTL，MVP 不持久化）
- **PurchaseService**：购买次数——`quantity + txHash`；web3j 查链上 Transfer 事件验证 `from=用户、to=后端地址、value=单价×数量`，txHash 幂等（DB 去重），成功后加次数
- **ProofService**：
  - 上传：per-user 冷却 60s（可配置）；流式 SHA-256；记录 PENDING
  - 存证：校验状态/余额 → 扣 1 次 → web3j `storeProof`（后端私钥，消耗 DocToken）→ 回写 txHash/状态
  - 校验：重新上传文件算 hash 对比，扣 1 次，返回一致/不一致
  - 列表：查询用户存证记录
- **AdminService**：
  - 登录：BCrypt 校验；**全局**失败锁定 60s（可配置，内存锁）
  - 查询：用户信息+购买次数、存证记录（可按用户筛选）、DocToken 发放记录（库）、兑换次数（读合约 `buyCount`）
  - 发放：web3j `mint(to, amount)` + 落库

web3j 合约交互用手写薄封装（Function 编码），不引入 solidity codegen 插件。
