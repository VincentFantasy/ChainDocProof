# 实施计划：购买次数时销毁 DocToken（存证不再销毁）

- 版本：v1.11
- 日期：2026-10-15
- 关联需求：`doc/story/5-购买时销毁DocToken-20261015.md`

## 一、背景与目标

**现状链路**：用户购买次数时把 DocToken **转给后端地址**，之后每次存证 / 校验由后端用管理钱包把 1 枚 DocToken **烧进 0 地址**（`DocProof.storeProof → token.transferFrom(admin, 0x0, costPerProof)`）。

**问题**：存证 / 校验时才从管理端钱包销毁代币，代币流经过后端，经济语义不直观。

**新链路（购买时销毁）**：
1. **买 DocToken**（不变）：钱包 `buyTokens(ETH→DocToken)`。
2. **买次数**（改）：用户**销毁自己的 DocToken**（新增 `DocToken.burn(uint256)`，打进 0 地址），金额 = 单价 × 数量；后端链上校验 `Transfer(用户 → 0x0, 金额)` 后发放 `t_user.credit_balance`。
3. **存证 / 校验**（改）：后端扣 `credit_balance`，`DocProof.storeProof` 只写链上记录、**不再销毁代币**；`DocProof` 去掉 `token` / `costPerProof` / `owner` / `onlyOwner` / `setCostPerProof`，构造函数改为无参。

**经济语义变化**：购买即全额销毁（预付费），不再按次从管理钱包销毁。这是已确认的设计（选项 A：购买时销毁）。

## 二、变更清单

### 2.1 合约（contract/）

**DocToken.sol**
- 新增 `burn(uint256 amount)`：销毁调用方自己的代币——`require(balanceOf[msg.sender] >= amount)`、`balanceOf[msg.sender] -= amount`、`totalSupply -= amount`、`emit Transfer(msg.sender, address(0), amount)`，加中文注释。
- 删除死代码 `burnFrom(address,uint256)`（当前无人调用）。
- 保留标准 `transfer/approve/transferFrom/allowance`（符合 ERC20 惯例，用户可互转，浏览器 / 工具兼容）。
- 更新头部注释（「存证合约通过 transferFrom/burnFrom 消耗」→「购买次数时用户 burn 销毁」）。
- `burn(uint256)` 选择子 = `0x42966c68`。

**DocProof.sol**
- 删除 `IToken` 接口、`token`、`owner`、`costPerProof`、`setCostPerProof`、`CostUpdated` 事件、`onlyOwner` modifier。
- `storeProof` 去掉 `token.transferFrom(...)`，只写 `proofs` / `hashIndex` / `ProofStored`（`Proof.owner` 字段保留，记录存证方）。
- `constructor()` 改为**无参**（不再接收 `_token` / `_costPerProof` / `_owner`）。
- 更新头部注释。

**重编译**：两个合约用 `npx -y solc@0.8.24` 重新编译并替换 `.bin`。

### 2.2 后端（server/）

- **ChainGateway.java**：`storeProof` javadoc 去掉「合约内会消耗调用方 DocToken 并销毁」；删除 `getCostPerProof()` / `setCostPerProof()`。`hasTransfer(txHash, token, from, to, value)` 为通用实现，无需改动（购买校验时 `to` 传 0 地址）。
- **PurchaseService.java**：`hasTransfer` 的 `to` 参数由 `chain.getAdminAddress()` 改为 0 地址常量（新增 `ZERO_ADDRESS = "0x" + "0".repeat(40)`）；javadoc 与失败文案「转给后端地址」→「从当前钱包销毁」；`expectedValue`（单价 × 数量）不变。
- **UserCreditController.java**：`credits()` 的 `CreditVo` 构造去掉 `backendAddress`；删除因此不再使用的 `chain` 字段 / 构造参数与导入；`purchase()` javadoc 更新。
- **CreditVo.java**：删除 `backendAddress` 字段 / 构造参数 / getter / setter，构造函数改为 `CreditVo(int balance, BigInteger unitPriceDocToken)`。
- **AdminService.java**：删除 `MAX_COST_PER_PROOF`、`getCostPerProof()`、`setCostPerProof()`；类 javadoc 去掉「存证费用调整」。
- **AdminController.java**：删除 `GET/POST /admin/proofs/cost` 两个接口及 `ProofCostReq` 导入。
- **ProofCostReq.java**：删除文件。

- **application.properties**：admin 私钥注释（不再用于「接收 DocToken」，仅用于 storeProof/mint 签名）、`unit-price-doc-token` 注释（每次购买需销毁的 DocToken）措辞更新；值不变。

## 三、部署影响

`DocToken`（新增 burn）与 `DocProof`（构造函数变更）**必须重新部署** → 两个新合约地址 → 同步更新 `server/.../application.properties` 的 `contract.doc-token` / `contract.doc-proof` 与 `client/src/config.js` 的两个常量；新 DocToken 需重新 mint 库存并重置汇率。管理钱包不再持有用于销毁的 DocToken。
